    ```yaml
      - name: Verify legal pages contain no placeholder tokens (CR-04 / TMG §5)
        shell: bash
        run: |
          set -e
          legal_dir="Frontend/src/app/(legal)"
          # Any [bracketed] token in a legal page is an unfilled operator placeholder.
          # Matches [Name], [Anschrift], [PLZ Ort], [kontakt@taxreader.de], etc.
          if grep -rnE '\[[^]]+\]' "$legal_dir"; then
            printf 'Legal placeholder check FAILED: bracketed placeholder tokens found above.\n'
            printf 'Operator must replace all [Name]/[Anschrift]/[PLZ Ort]/[kontakt@...] tokens with real contact data before deploy.\n'
            exit 1
          fi
          printf 'Legal placeholder check passed.\n'
    ```

    Important details:
    - Quote `"$legal_dir"` so the `(legal)` parentheses are passed literally to grep (the path exists on disk with literal parens).
    - `grep -rnE` prints the offending file:line:match to the CI log (helps the operator), then exits 0 when matches exist — so we invert: when grep SUCCEEDS (matches found) we `exit 1`. With `set -e`, a no-match grep returns 1, which would abort the step; guard against that by keeping the grep inside the `if` condition (the `if` consumes the exit code, so `set -e` does not abort on the no-match case).
    - Do NOT modify any other job (backend-build-test, frontend-lint-build) or the existing hygiene step.

    Then document the operator action: append a row/note to `.planning/phases/06-legal-consent-data-export/06-LEGAL-REVIEW.md` (or, if a clearer tracking file exists, 06-AVV-TRACKING.md) stating: "Operator action: replace [Name]/[Anschrift]/[PLZ Ort]/[kontakt@taxreader.de] in all four (legal) pages with real legal-entity data. CI guard (hygiene-check) blocks merge until done." Use German is not required for this planning note — keep it as an operator tracking line.
