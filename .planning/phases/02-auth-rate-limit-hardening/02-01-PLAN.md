<objective>
Replace the single-column `users.refresh_token` model with a multi-row `refresh_tokens` table backed by an `IRefreshTokenService` that hashes tokens with an HMAC-SHA256 pepper, rotates on every refresh, and revokes ALL of a user's tokens when a revoked token is replayed.

Purpose: Multi-device-safe authentication (D-01..D-04, D-15) — phone + laptop sessions coexist, a leaked token replayed after rotation triggers full revocation, and a DB-only leak cannot forge a valid token because the HMAC pepper lives in env vars.

Output:
- New `refresh_tokens` table (10 columns per D-02) created via single EF migration that ALSO drops the legacy `users.refresh_token` + `users.refresh_token_expires_at` columns
- `IRefreshTokenService` with `IssueAsync`, `ValidateAndRotateAsync`, `RevokeAllForUserAsync`
- `AuthService` refactored to delegate refresh-token writes to the new service
- `AuthEndpoints` /login + /register + /refresh extract User-Agent + IP from HttpContext and pass them through
- New `RefreshToken__HashKey` env var wired in docker-compose.yml and .env.example
- Test scaffolding (Wave 0) covering all AUTH-01 behaviors per VALIDATION.md
