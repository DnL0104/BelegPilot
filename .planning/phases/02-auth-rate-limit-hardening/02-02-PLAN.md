## STRIDE Threat Register (ASVS Level 1, V2 + V4 + V7)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering | Account deletion via stolen access token (attacker has JWT but not password) | mitigate | D-10 password re-verify via `BCrypt.Net.BCrypt.Verify` — same factor that gates login. Without the password, an attacker holding only the access token cannot delete the account. D-12 also attaches `auth-strict` (5/min per `sub`) to make brute-force probing infeasible. ASVS V2.2 + V4.1. |
| T-02-18 | Information Disclosure | Login enumeration via /account 401 (attacker probes whether email→password combinations are valid) | accept | Endpoint already requires bearer JWT — caller is authenticated, so the attacker has already proven they ARE the user. The 401 surfaces ONLY their own password being wrong. No enumeration risk because the email is implicit (not in request body). ASVS V7.4 |
| T-02-19 | Tampering | Refresh tokens persist after user deletion (zombie sessions) | mitigate | D-13 step 2: `refreshTokenService.RevokeAllForUserAsync(userId, ct)` runs BEFORE `dbContext.Users.Remove(user)`. Even if the FK CASCADE would have dropped the rows automatically, the explicit revoke ensures: (1) operations are auditable (Phase 6 LEG-08 will log the revoke as a separate event), (2) any in-flight `RefreshAsync` calls fail BEFORE the user record is deleted (preventing a small race window). ASVS V3.2 — session termination. |
| T-02-20 | Repudiation | Account deletion is not audit-logged | accept | Phase 6 LEG-08 owns `audit_log` table + `AuditLogger`. Phase 2 emits the deletion via Serilog only (structured log entry). Audit-log integration deferred to LEG-08. |
| T-02-21 | EoP | CSRF on DELETE /auth/account (cross-origin form-submission tricks user into deleting account) | mitigate | Bearer JWT (not cookie) means no implicit-credentials surface — a cross-origin POST cannot include the user's `Authorization: Bearer ...` header without explicit JS. Phase 1 D-07 CORS deny-all policy further blocks cross-origin XHR. ASVS V4.2 — CSRF protection via token-based auth + same-origin. |
| T-02-22 | Information Disclosure | Wrong-password 401 leaks timing signal | accept | `BCrypt.Verify` is constant-time by design (BCrypt-Net-Next 4.0.3 docs). Timing leakage <1ms across correct vs incorrect passwords. ASVS V6.2 — constant-time comparison. |
