## Spacing Scale

Declared values (multiples of 4 only). All phase 5 surfaces use this scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline chip padding (`px-2 py-0.5`) |
| sm | 8px | Compact element spacing, card inner gap (`gap-2`) |
| md | 16px | Default element spacing, card padding (`px-4`) |
| lg | 24px | Section padding, dialog section breaks |
| xl | 32px | Layout column gaps |
| 2xl | 48px | Major section breaks within billing page |
| 3xl | 64px | Page-level vertical spacing |

Exceptions:
- Touch targets (buttons, checkboxes in `TopUpDialog` legal gate): minimum 44px height per WCAG 2.5.5 — achieved via `min-h-11` (44px) on interactive controls
- Sidebar nav item height: 40px (`h-10`) — matches existing `SidebarMenuButton` pattern

Source: existing component audit (`app-sidebar.tsx`, `top-up-dialog.tsx`, `card.tsx`)

## Surface Specifications

### Surface 1: `/billing` Page

**Route:** `Frontend/src/app/(authenticated)/billing/page.tsx` (new file)
**Layout:** Full-width content area within existing authenticated shell (sidebar + header)

#### Section 1.1: Payment-Success Banner
- Condition: `searchParams.get("payment") === "success"`
- Component: `Alert` variant `default` with `AlertTitle` + `AlertDescription`
- Icon: `CheckCircle` (lucide) in `text-primary` (emerald)
- Title: "Zahlung erhalten"
- Body: "Ihre Credits werden in Kürze gutgeschrieben. Dies kann bis zu 30 Sekunden dauern."
- Dismissal: Auto-hide after 15 s (same window as polling stops); OR manual close button
- Position: Top of page content, above all cards, full-width

#### Section 1.2: DemoMode Persistent Banner
- Condition: API returns `isDemoMode: true` in any payment response OR detected via env
- Component: `Alert` with amber color contract (see Color section)
- Icon: `FlaskConical` (lucide)
- Text: "Demo-Modus — keine echten Zahlungen. Credits werden direkt gutgeschrieben."
- Persistence: Always visible when DemoMode active (not dismissible)
- Position: Top of page, above balance card (below success banner if both present)

#### Section 1.3: Token Balance Card
- Component: `Card` (default size)
- `CardHeader`: Title "Guthaben", `CardAction` contains `Button` variant `default` label "Credits aufladen" (opens `TopUpDialog`)
- `CardContent`: Large balance figure — `text-3xl font-semibold` — format: `{N} Credits`
  - Positive: `text-foreground`
  - Zero: `text-muted-foreground`
  - Negative: `text-destructive` — append " (Konto gesperrt)" in `text-sm text-destructive`
- `CardFooter` (when balance negative): Warning row — "Neue Uploads sind gesperrt. Bitte laden Sie Credits auf, um fortzufahren." `text-sm text-destructive`
- Loading: Render `Skeleton className="h-9 w-24"` in place of balance figure

#### Section 1.4: Transaction History Table
- Component: `Card` wrapping `Table`
- `CardHeader` title: "Transaktionsverlauf"
- Table columns: Datum | Beschreibung | Credits | Typ
  - Datum: formatted `dd.MM.yyyy` (German locale via `format.ts`)
  - Credits: `+{N}` in `text-primary` for positive; `-{N}` in `text-destructive` for negative/refund
  - Typ: `Badge` — "Kauf" (default), "Rückerstattung" (destructive outline), "Verbrauch" (secondary)
- Pagination: Show last 20 entries; no pagination controls in Phase 5 (last-20 API constraint)
- Empty state: Single-row cell `colspan={4}` — "Noch keine Transaktionen vorhanden." `text-sm text-muted-foreground text-center py-8`
- Loading: 5 `Skeleton` rows, each `h-10`

#### Section 1.5: Invoice List
- Component: `Card` wrapping `Table`
- `CardHeader` title: "Rechnungen"
- Table columns: Rechnungsnummer | Datum | Betrag | Aktionen
  - Betrag: `Intl.NumberFormat('de-DE', { style: 'currency', currency: 'EUR' })` format
  - Aktionen: `Button` variant `outline` size `sm` label "PDF herunterladen" — `href={invoice.invoicePdfUrl}` target `_blank`; disabled + `text-muted-foreground` when `invoicePdfUrl` is null (invoice not yet finalized)
- Empty state: "Noch keine Rechnungen vorhanden." — same treatment as transaction history
- Loading: 3 `Skeleton` rows

#### Section 1.6: Payment Method Management
- Component: `Card`
- `CardHeader` title: "Zahlungsmethode"
- `CardDescription`: "Zahlungsmethoden verwalten, gespeicherte Karten ändern oder Zahlungshistorie einsehen."
- `CardFooter`: `Button` variant `outline` — label "Zahlungsmethode verwalten" with `ExternalLink` icon (lucide, 14px)
- Action: `onClick` calls `createPortalSession()` mutation → on success `window.location.href = data.url`
- Loading state: Button shows `Loader2` spinner (same pattern as `TopUpDialog`)
- Error state: sonner `toast.error("Weiterleitung fehlgeschlagen. Bitte versuchen Sie es erneut.")`

#### Page Layout Structure
```
/billing page
├── [DemoMode banner — conditional]
├── [Payment success banner — conditional]
├── <h1 class="text-2xl font-semibold">Credits & Abrechnung</h1>
├── Section grid: md:grid-cols-2 gap-6
│   ├── Balance Card (col-span full on mobile, col-1 on md)
│   └── Payment Method Card (col-2 on md)
├── Transaction History Card (full width)
└── Invoice List Card (full width)
```

### Surface 2: `TopUpDialog` (Modified)

**File:** `Frontend/src/components/tokens/top-up-dialog.tsx` (existing, modified)

#### Legal Gate Section (new — inserted between package selector and footer)

The legal gate is inserted between the package grid and the `DialogFooter`. It contains two checkboxes with their labels. Neither is pre-ticked.

**AGB Checkbox:**
- Component: `Checkbox` (new shadcn component) + `Label`
- ID: `agb-checkbox`
- Label text: `Ich akzeptiere die ` + `<Link href="/agb" className="underline underline-offset-2">Allgemeinen Geschäftsbedingungen</Link>` + `.`
- The `/agb` link is a Phase 6 placeholder; it may 404 in Phase 5 — this is acceptable

**Widerrufsrecht Checkbox:**
- Component: `Checkbox` + `Label`
- ID: `widerrufsrecht-checkbox`
- Label text (verbatim — do NOT paraphrase or shorten): "Ich verlange ausdrücklich, dass mit der Ausführung des Vertrags sofort begonnen wird. Mir ist bekannt, dass ich hierdurch mein Widerrufsrecht verliere."
- Rendered at `text-sm` — not `text-xs` — for legal legibility

**Layout:**
```
<div class="space-y-3 py-2">
  <div class="flex items-start gap-3">
    <Checkbox id="agb-checkbox" ... />
    <Label htmlFor="agb-checkbox" class="text-sm leading-normal cursor-pointer">
      Ich akzeptiere die <Link href="/agb">Allgemeinen Geschäftsbedingungen</Link>.
    </Label>
  </div>
  <div class="flex items-start gap-3">
    <Checkbox id="widerrufsrecht-checkbox" ... />
    <Label htmlFor="widerrufsrecht-checkbox" class="text-sm leading-normal cursor-pointer">
      Ich verlange ausdrücklich...
    </Label>
  </div>
</div>
```

`items-start` (not `items-center`) is required because the Widerrufsrecht label wraps to 2–3 lines — checkbox must align to the first line.

#### "Kaufen" Button State Machine:
- Disabled: `!agbChecked || !widerrufsrechtChecked || isPending`
- Enabled: both checkboxes ticked and not pending
- Loading: `Loader2` spinner + text "Weiterleitung..."
- Normal enabled: label = `{selected} Credits kaufen – {price}` (e.g. "200 Credits kaufen – 14,99 €")

#### DemoMode Banner in Dialog (when DemoMode active):
- Component: `Alert` with amber styling (see Color section)
- Text: "Demo-Modus — keine echten Zahlungen. Credits werden direkt gutgeschrieben."
- Position: Below DialogDescription, above balance display row
- Not dismissible

#### Checkout Flow:
- On "Kaufen" click: call `createCheckoutSession({ credits: selected, waiverAccepted: true, agbAccepted: true })`
- On success: `window.location.href = data.checkoutUrl` (Stripe redirect)
- On error: `toast.error("Bezahlung konnte nicht gestartet werden. Bitte versuchen Sie es erneut.")`
- Dialog stays open during pending state (user must not close and lose the checkout URL)

## Interaction States

### `TopUpDialog` State Machine

```
INITIAL
  → package selected (default: 200 credits)
  → both checkboxes unchecked → "Kaufen" DISABLED

LEGAL_GATE_SATISFIED
  → both checkboxes checked → "Kaufen" ENABLED

PENDING (after "Kaufen" click)
  → Button shows Loader2 + "Weiterleitung..."
  → Dialog stays open
  → All controls disabled

SUCCESS
  → window.location.href = checkoutUrl
  → dialog closes via navigation (Stripe redirect)

ERROR
  → toast.error(message)
  → Dialog returns to LEGAL_GATE_SATISFIED state (checkboxes remain ticked)
  → User can retry immediately
```

### Billing Page Polling State (`/billing?payment=success`)

```
ON MOUNT (if ?payment=success present)
  → setIsPolling(true)
  → Show success banner
  → refetchInterval = 3000ms on tokenBalance query
  → setTimeout(15_000) → setIsPolling(false)

POLLING ACTIVE
  → Balance card refreshes every 3s
  → Skeleton not shown during refetch (data remains from last successful fetch)

POLLING STOPS (15s elapsed)
  → refetchInterval returns to standard (30s)
  → Success banner auto-hides OR persists until user navigates away (implementation choice)
```

## Accessibility Notes

- All `Checkbox` components must have associated `Label` via `htmlFor`/`id` pairing
- The Widerrufsrecht label wraps to multiple lines — use `items-start` on the flex container, not `items-center`
- "PDF herunterladen" links open in `target="_blank"` — add `rel="noopener noreferrer"`
- Balance figure uses `aria-label="{N} Credits Guthaben"` for screen reader context
- Negative balance state: use `role="status"` on the warning `CardFooter` content
- DemoMode banner: use `role="alert"` so screen readers announce it on mount
